# RobotControl 整体架构

## 各端定位

| 端 | 目录 | 技术栈 | BLE 角色 | 功能定位 |
|---|---|---|---|---|
| 控制台 | [master-app](../master-app) | Kotlin + WebView + HTML/JS | GATT Server | 机器人控制主界面，提供完整控制面板（显示名 **Master**） |
| 手机端 | [slave-app](../slave-app) | Kotlin 原生（纯代码 UI） | GATT Client（连接 Console / win-app） | 状态接收展示终端，双列展示任务和语音（显示名 **Slave**，图标与 master 同族色相区分） |
| 手表端 | [watch-app](../watch-app) | Kotlin 原生（WearOS） | GATT Client（连接 Phone） | 腕上轻量状态查看，三页面横滑切换 |
| Windows 桌面版 | [win-app](../win-app) | Electron + HTML/JS + C# BLE 宿主 | GATT Server（`RobotControl-Win`） | 控制台桌面端：前置 USB 启动器 + master-app www 副本控制台，桥接等效；C# 宿主实现 7500 服务外设广播，slave-app 可连接 |

## BLE 连接拓扑

```
┌──────────────────────┐        ┌──────────────────────┐        ┌──────────────────────┐
│     master-app      │        │      slave-app       │        │      watch-app       │
│   (RobotControl-     │  BLE   │   (RobotControl-     │  BLE   │                      │
│     Console)         │◄───────│     Phone)           │◄───────│                      │
│  GATT Server         │ Client │  GATT Client + Server│ Client │  GATT Client         │
│  - 广播 Service 7500 │        │  - 连接 Console      │        │  - 连接 Phone        │
│  - 4 Characteristic  │        │  - WatchGattServer   │        │  - 接收数据展示      │
│  - 向前端推送数据    │        │    (代码存在但未启用) │        │                      │
└──────────────────────┘        └──────────────────────┘        └──────────────────────┘
          ▲                                ▲                                ▲
          │                                │                                │
          │  Mode / Emotion / Tasks / Voice 向下推送；Mode 反向推送（Client→Server） │
          └────────────────────────────────┴────────────────────────────────┘
```

## 数据流方向

数据以 Console 为唯一数据源、经 BLE Notification 向下推送为主，另有 Client→Server 上行通道（Heartbeat 心跳、ApiKey 同步、Mode 反向推送）：

1. **Console → Phone**：Phone 作为 GATT Client 连接 Console（master-app / win-app）的 GATT Server，订阅 7 个 Characteristic（Mode/Emotion/Tasks/Voice/Heartbeat/ApiKey/UiLang）的通知
2. **Phone → Watch**：（设计意图，但当前代码中 WatchGattServer 未启用；Watch 实际通过扫描并连接名为 RobotControl- 前缀的设备，当前代码中 Phone 未启动 GATT Server，Watch 扫描到的是 Console）
3. **Phone → Console（反向，1.7.0）**：slave-app 长按胶囊选模式或语音识别命中后，经 `ConsoleBleClient.writeMode(ordinal)` 写入 Mode(7501)（1 字节 ordinal，仅 0-3 生效）反向切换控制台模式；控制台切换并高亮后经既有链路回推模式/语音，手机端据此把通知标题显示为「推送成功」（4s 回声窗口 + 兜底，防同一次推送双弹）。协议细节见 BLE 协议文档「反向模式推送」
4. **ApiKey(7506) 双向对齐（1.11.0）**：Slave 连接后读取 7506 取 Master 侧 Key 并按同步矩阵裁决（一侧空/失效另一侧可用 → 以有效方为准；双方可用不同 → 各用各的；详见 BLE 协议文档 7506 节）——Master→Slave 方向靠 Master 把可用 Key 预置进 7506（前端 `syncCurrentStateToNative` 推送）+ Slave READ/Notify；Slave→Master 方向沿用 7506 写入，Master 侧前端按矩阵裁决后落库

> **注意**：watch 的 PhoneBleClient 仍按 `RobotControl-` 名称前缀扫描；phone 的 ConsoleBleClient 按服务 UUID 7500 过滤并接受“名称前缀匹配”或“广告含服务 UUID 7500”的设备，因此可连接 master-app 或 win-app。

## 各端技术栈详情

### master-app（控制台）
- **Activity**：[MainActivity.kt](../master-app/app/src/main/java/com/robotcontrol/console/MainActivity.kt) 单 Activity；`launchMode=singleTask`，Manifest 附带 `robotcontrol://console` 深链 intent-filter（VIEW+DEFAULT+BROWSABLE，浏览器端「打开 App」拉起入口，重复拉起经 onNewIntent 送达现有实例）
- **UI**：全部由仓库根 [www/芮誊T系列仿人男性机器人控制台V1.1.html](../www/芮誊T系列仿人男性机器人控制台V1.1.html) 渲染（构建期由 Gradle `syncWww` 同步进 App 的 assets/www/，禁止手改）
- **BLE Server**：[RobotGattServer.kt](../master-app/app/src/main/java/com/robotcontrol/console/ble/RobotGattServer.kt) 单例
- **JS Bridge**：通过 `WebView.addJavascriptInterface` 绑定名为 `Android` 的对象
- **前端资源**：`app/src/main/assets/www/` 为 Gradle `syncWww` 任务（preBuild 自动执行，排除 `.mimosa` 工具目录，含任意层级子目录 `**/.mimosa`）从仓库根 `www/` 同步的产物（gitignore），HTML/CSS/JS/图片/字体均随 `www/` 单源维护

### slave-app（手机端）
- **Activity**：[MainActivity.kt](../slave-app/app/src/main/java/com/robotcontrol/phone/MainActivity.kt) + [QrScanActivity.kt](../slave-app/app/src/main/java/com/robotcontrol/phone/QrScanActivity.kt)
- **UI**：纯 Kotlin 代码动态构建，无 Compose，使用传统 ViewGroup
  - 顶部固定区：`topFixedContainer`（胶囊模式显示 + 情绪面板 + 黑色渐变遮罩）
  - 下部滚动区：`scrollView` 内双列布局（任务列表 | 语音列表）
- **BLE Client**：[ConsoleBleClient.kt](../slave-app/app/src/main/java/com/robotcontrol/phone/ble/ConsoleBleClient.kt) 单例连接 Console
- **数据中心**：[PhoneDataStore.kt](../slave-app/app/src/main/java/com/robotcontrol/phone/data/PhoneDataStore.kt) 单例 + 观察者模式
- **自定义 UI 组件**：[EmotionPanelView.kt](../slave-app/app/src/main/java/com/robotcontrol/phone/ui/EmotionPanelView.kt)
- **通知推送**：收到语音消息时发送系统通知（标题「主人指令」；反向推送回声为「推送成功」，1.7.0）
- **模式反向推送（1.7.0）**：长按顶部胶囊弹模式菜单（4 项+关闭）或语音识别命中 → `ConsoleBleClient.writeMode(ordinal)` 写入 Mode(7501)；未连接时提示「未连接控制面板」
- **语音识别（1.7.0，1.9.1 加固，`speech/` 包）**：右上角圆形麦克风按钮单击常态开/关（RECORD_AUDIO 权限、前台恢复/后台停止）；本地识别按**三级引擎逐级回退**（设备端离线 → 系统识别器离线优先 → 系统识别器允许联网；同一引擎连续 3 次错误换下一级，Manifest 需 `<queries>` 声明 `android.speech.RecognitionService`，否则 Android 11+ 包可见性过滤下查不到识别服务），识别文本过 `VoiceCommandMatcher` 本地规则（按读音拼音匹配、否定词排除——英文按词边界、语言门控跟随 7507），命中即切换模式；仅当本地得到大段文本未命中且满足门槛（≥4 字、音频 ≥1.2s、间隔 ≥4s、无并发）才把 PCM 音频发 MiMo `mimo-v2.5-asr` 云端兜底；设置页（BLE 对话框）「识别引擎调用云端（MiMo ASR）」开关关闭后仅本地识别，三级引擎全失败且有云端条件时退化为「仅云端」

### watch-app（手表端）
- **Activity**：[MainActivity.kt](../watch-app/app/src/main/java/com/robotcontrol/watch/MainActivity.kt) 单 Activity
- **UI**：纯 Kotlin 代码动态构建，圆形屏幕适配
  - 三页面横向滑动容器：[PageContainer.kt](../watch-app/app/src/main/java/com/robotcontrol/watch/ui/PageContainer.kt)
  - 页面 0：EmotionView（情绪展示）
  - 页面 1：TaskPageView（任务列表，默认显示）
  - 页面 2：VoicePageView（语音消息）
- **BLE Client**：[PhoneBleClient.kt](../watch-app/app/src/main/java/com/robotcontrol/watch/ble/PhoneBleClient.kt) 单例
- **数据中心**：[WatchDataStore.kt](../watch-app/app/src/main/java/com/robotcontrol/watch/data/WatchDataStore.kt) 单例 + 观察者模式
- **旋转表冠**：支持旋转表冠滚动 Task/Voice 页面列表

### win-app（Windows 桌面版）
- **入口**：[win-app/app/main.js](../win-app/app/main.js)：启动器 + 主控制台窗口、固定 `app://design` / `app://bundle` 协议、USB 检测、IPC 桥接；`requestSingleInstanceLock` 单实例锁（second-instance 聚焦已有窗口）与 `setAsDefaultProtocolClient('robotcontrol')`（`robotcontrol://console` 深链，浏览器端「打开 App」拉起入口；开发模式注册须显式传 app 路径）
- **BLE 宿主**：`ble-host/`（C#，Windows GATT Service Provider，设备名 `RobotControl-Win`），由主进程经命名管道拉起；`app/ble-bridge.js` / `app/ble-protocol.js` 负责进程管理与 JSON 行协议
- **启动器**：`design/launcher.html`，Acrylic 毛玻璃 + DWM 原生圆角；USB 热插拔检测（`app/usb.js` / `usb-watcher.js`，PowerShell WMI 轮询）与多设备匹配规则；huimo/color 精灵图状态机；F2 测试模式仅本次启动生效；点击设备按钮进入控制台
- **桥接**：[win-app/app/preload.js](../win-app/app/preload.js)：`contextBridge` 暴露 `window.Android`（与 Android JS Bridge 同名等价）+ `window.consoleAPI`；[win-app/app/preload-launcher.js](../win-app/app/preload-launcher.js) 暴露 `window.electronAPI`
- **前端**：`win-app/app/www/` 为仓库根 `www/` 的构建期同步镜像（`scripts/sync-www.ps1`，npm prestart/predist 自动执行，gitignore），经 `app://bundle` 加载，启动为 启动器 → 闪屏 → 登录 → 三栏布局
- **窗口控制**：自绘仿 Win11 按钮（启动器最小化/关闭，控制台最小化/最大化还原/关闭），替代原生 WCO（原生按钮无法与毛玻璃/暗绿顶栏融合）
- **能力边界**：BLE GATT Server 由 `ble-host/`（C#，Windows GATT Service Provider）提供，设备名 `RobotControl-Win`，需蓝牙适配器支持 Peripheral 模式（不支持时回退“暂不支持”提示）；MiMo TTS 经主进程 `net.fetch` 代理；运行时数据全部持久化在 `win-app/huancun/`（首次启动自动迁移旧 `%APPDATA%` 数据）

### 前端单源架构（www 唯一主线）

- 唯一源码：仓库根 `www/` 下的主 HTML（`芮誊T系列仿人男性机器人控制台V1.1.html`），浏览器端直接打开，master-app 与 win-app 构建期同步取用。
- 浏览器端 MiMo TTS 密钥：Key 不内置于 HTML、不做任何本地文件自动注入，纯浏览器打开时需在控制台设置中手动输入（保存至 localStorage `mimoApiKey`，读取时经引号清洗）；Key 缺失时 MiMo 调用报错并回退系统 speechSynthesis 引擎，属预期降级。Chrome 允许 `file://` 页面跨域 fetch https（服务端 CORS 全开放），夸克等 UC 内核浏览器默认拒绝该请求，即使输入 Key 也可能无法调用 MiMo——手机端需 MiMo 请使用 master-app（WebView 经 Native `mimoFetchAsync` 代理请求，不依赖浏览器跨域）。
- 按需资源：`css/win.css` 与 `js/win.js` 仅在 Electron（`window.consoleAPI`）端加载；`css/android.css` 仅在 Android（`window.Android`）端加载，承载 Android 终端形态设计差异（充电灵动岛显示时机、旋转原点、暂停规则）；`js/android.js`（键盘/安全区/IME，定义全局 `updateSafeAreaInsets` 供原生回调）三端加载但仅在 Android WebView 生效——安全区轮询与 resize/orientationchange 监听经 `window.Android && !window.consoleAPI` 门控，桌面/浏览器零开销；`css/app-launch.css` 与 `js/app-launch.js`（浏览器端 App 拉起引导）仅纯浏览器（`!consoleAPI && !Android`）由平台引导脚本注入。
- 界面多语言（**v1.10.0 起默认英文**：按设备语言自动匹配——`zh*` 显示中文、其余/检测不到显示英文——并支持手动切换；手表端不参与）：
- **语言决策顺序（三端统一）**：① 用户手选（唯一持久化的值）→ ② 设备语言自动检测（**结果不落盘**，每次启动重新检测）→ ③ 兜底英文。www 侧链路：`localStorage robot_ui_lang` → `consoleAPI.bootLang`(win-app) → `navigator.languages/language` → `en`；master-app `ConsoleI18n` 与 slave-app `PhoneI18n` 无手选标记（`lang_manual`）时按 `Locale.getDefault().toLanguageTag()` 检测；win-app `app/i18n.js` 用手选 → `app.getLocale()` → `en`（旧 `huancun/i18n-lang.json` 无 `manual` 字段者视为手选——旧实现只在手切时写入）。
- `js/i18n.js`（head 同步加载，先于其余脚本）为运行时覆盖层——中文源文案一字不改，EN 模式下按 DICT 替换 DOM 文本节点与 `title/placeholder/aria-label/alt` 属性（整句映射为主、拼接片段为辅，覆盖自检/系统更新全流程输出与终端文案），MutationObserver 跟进动态内容，`alert/confirm` 经补丁透传翻译；语言存 localStorage `robot_ui_lang`，设置页「语言」组（`#lang-setting`，中文/English 按钮 + `lang-active` 选中态）切换即时生效、刷新保持，`document.title` 与 `<html lang>` 同步；设置页语言组提示按「默认按设备语言自动匹配（中文设备显示中文，其余显示英文）」表述。术语遵循 T31-750 英文版说明书并用词规则：显示层 robot 作 Android（Male Android / Android Control Console；Simulated Human Mode / Test Mode / Self-check / Artificial Semen / Appearance-Data 等照旧，公司名 Rt5 A.I. Fictional Liability Company）；新增/修改 UI 文案需向 DICT 补对应条目。**写入守卫（硬性）**：替换仅在与当前值实际不同才落笔——若按缓存的中文原文比较后无条件重写，同值写入会再次触发 MutationObserver 形成微任务自反馈死循环、卡死渲染主线程（画面停在旧帧、输入无响应，Android WebView 实测复现），www 与 win-app 启动器两端覆盖层均带守卫。登录过渡屏文案（`app-boot.js` playLoginBoot）为 EN 模式写入时直译，不依赖 Observer，避免中文闪帧。原生随动：win-app 主进程文案经 `win-app/app/i18n.js`（`huancun/i18n-lang.json` 持久；IPC `i18n-get-lang`/`i18n-set-lang` 与页面双向同步）——启动器窗口标题、主窗口标题、BLE 宿主错误文案，闪屏页标题经 `consoleAPI.getUiLang` 随动，启动器界面经 `design/launcher-i18n.js` 覆盖层（`electronAPI.getUiLang`），启动器设置面板顶部有「界面语言」切换组（中文/English 按钮，选中态由 `launcher-lang-changed` 事件统一刷新；写入 localStorage `robot_ui_lang` + IPC `i18n-set-lang`）；**启动器切语言后主控制台跟随**：`preload.js` 顶层 `sendSync('i18n-get-lang-sync')` 经 `consoleAPI.bootLang` 在页面脚本前带回，i18n.js 头脚本以主进程文件为初始语言事实源并对齐 localStorage（浏览器/Android 无此桥维持 localStorage 行为）；master-app 原生 Toast/PDF 提示经 `ConsoleI18n`（SharedPreferences `robot_ui_lang`），页面经 JS 桥 `Android.setUiLang` 同步，启动器标签随系统语言走 `values-en/strings.xml`；slave-app 原生文案经 `PhoneI18n`（**v1.10.0 起不再跟随发送端**：已移除 BLE `7507(UiLang)` 的订阅、初读与 `onLangReceived`，语言改为本机设备检测 + 蓝牙对话框手动切换；`0x00`/`0x01`/`0xFF` 的语义与服务端推送保持不变，仅本端不再消费，旧版客户端仍可订阅；任务名/语音消息/模式名在渲染点走 `t()`），启动器标签与胶囊初始文案走 `values-en/strings.xml`。**EN 自适应窄体**（排版密度向中文看齐，不做全页缩窄）：`webfonts/MonoNarrow-*.woff2`（JetBrains Mono VF 实例化+75% 横压，生成工具 `tools/gen-mono-narrow.py`）；i18n.js `fitPass` 逐块实测 EN 与中文原文行高/宽度（块级容器+文本直接父元素双向比对），仅超宽/多行者加 `.i18n-cn-fit`（`font-stretch: condensed` 窄面 + 'MonoNarrow' 常规窄家族，声明见 fonts-face.css/fonts.css），窄体仍放不下时分级缩小字号（0.9→0.6 倍 + -0.03em 字距，仅作用于文本元素本身，板块布局不变）、完整术语保持单行；终端/日志/代码滚动区与浮窗为拟合豁免区（正常字宽）；中文模式（无手选且设备为中文）无拟合类、字宽逐位不变。窄面字体已去 TrueType hinting（缩放轮廓配原 hinting 会在小字号渲染出字母间伪影），详见 `docs/reademe.md` 1.3.5。EN 首屏/切换经 `html.i18n-fitting` 遮罩一步到位显形（头脚本挂载早于首帧，全量拟合防抖 30ms、4s 兜底）。术语用词：显示层 robot 一律作 Android（Male Android 等），机械度=Robotic，公司名=Rt5 A.I. 每文件哈希校验（同 path 内容变更自动重拉）；清单外同源 GET（如 PDF）运行时缓存；缓存名 `rc-www-<version>` 版本化，切换按哈希从旧缓存**增量拷贝**未变更条目（版本指针持久化于 `rc-meta` 缓存——SW 进程回收重启后内存 state 归零仍能找到拷贝源）；**变更文件先预下载进新缓存、全部成功后才删其余旧缓存**（预下载不全则保留旧缓存兜底、下次同步再清——否则切换后恰好断网时，懒下载的变更文件会缺席致页面残缺，如 `app-clawbot.js` 缺失使 IM 通知推送设置整块空白），cache-miss 且网络失败时再做全局缓存兜底。**更新提示**：页面发 `RC_SW_CHECK_VERSION` 附带 `rc_full_cache` 版本号，SW 版本同步后**总是回发** `RC_CACHE_STATE`（version/outdated/changed；离线拿不到清单则不回发，页面按"未知"处理）——platform-bootstrap 监听：`outdated` 且全量模式且变化不全在例外集（仅 `pic/login/Background.webp`）时提示重新缓存——登录层可见时走 `.rc-cache-banner` 底部横幅（z 965，macOS 通知 z 948 会被登录层 950 盖住），否则桌面弹 macOS 通知、移动端横幅，点击打开缓存控制台；并向页面广播 `rc-cache-state` 事件；app-launch 据此控制常规弹窗的缓存入口显隐——**与服务器一致（或未知/离线）时不提醒缓存、入口隐藏**，确认有差异才显示（末位弱化样式），重缓存完成经 `rc-full-unlocked` 复位。

## First Run（首次启动）统一流程（v1.10.0）

四端首次启动统一为「先完成一次激活设置，再进入主界面」，各端形态不同但共用同一份激活表单实现（www 控制台的 `#activation-modal` 十组设置）：

| 端 | 首启表现 | 完成标记 |
|---|---|---|
| master-app | 原生品牌 PV 播完（`checkSplashDismiss()` 等 `videoEnded && webReady`）后必定先显示激活页，完成/跳过后 `initApp()` 进主界面；**该平台仍无登录界面** | localStorage `robotActivated`（WebView） |
| win-app | 首次启动时激活窗口（1080×860，`app://bundle/<控制台页>?firstrun=1`）**先于启动器出现**；完成后经 IPC `firstrun-done` → 关窗 → 建启动器继续原流程 | `huancun/activated.json` + 控制台 localStorage |
| slave-app | 原生首启界面（`firstRunContainer` 覆盖主界面） | SharedPreferences `first_run_prefs.first_run_done` |
| 浏览器 | 登录页位置显示激活页（v1.6.0 起） | localStorage `robotActivated` |

- **www `?firstrun=1` 模式**：只渲染激活页（登录层与主界面都不显示），完成/跳过后派发 `rc-firstrun-done` 并回调宿主（`consoleAPI.firstRunReady(needsForm)` / `firstRunDone`）；表单实现与主控制台共用，激活结果直接落同一套 localStorage。
- **激活页版面（同版本二轮重构）**：十组表单与存储键不变，版面随宽度自适应——移动端（≤749px）整屏平铺（去卡片、满宽满高、顶/底避开系统安全区，[安全区变量见下方「平台适配」]），桌面（≥1100px）容器加宽至 `min(1180px, 92vw)` 并两列排布（`column-count`，阅读顺序仍 1→10）；激活页原右上角语言胶囊已删除（第 1 组「语言」即入口），长标签/长值用自适应高度文本框完整显示。实现要点见 [master-app 文档](master-app/reademe.md)「激活页版面」。
- **win-app 按需显形**：激活窗口先隐藏加载，页面判定**确实需要填表**（未激活）才显示；已激活用户（旧版本升级、或宿主标记丢失）经 `firstRunReady(false)` 直接收尾回启动器，不闪窗；3s 兜底防信号异常。用户直接关闭激活窗口视为跳过（不写标记，控制台内激活页仍是兜底）。
- **完成标记与语言标记互相独立**：语言手选（`lang_manual` / `i18n-lang.json` 的 `manual`）与首启完成互不影响。
